# TargetForge 更新总结（2026-11-16 ~ 11-17）

本文归档最近两天的主要改动，便于用户和后续维护者了解当前状态。

## 1. 一键启动器

- 新增 `start.bat` / `start.ps1`
  - 检查 Python 与 `.venv`；
  - 首次运行自动创建虚拟环境并安装 `requirements.lock`；
  - 启动 WebUI 并输出带 token 的访问地址。
- 新增 `serve.bat` / `serve.ps1`
  - 日常服务启动入口；
  - 自动探测可用端口：`11451 / 14514 / 91781 / 78139`；
  - 支持 `-WithEmulator`、`-CheckOnly`、`-Port`；
  - 启动后设置控制台标题：`靶机工坊 TargetForge | http://127.0.0.1:<port>/?token=<token>`。

## 2. 数据层：彻底只读 STC

- catalog 构建直接读取 `dataMiner/stc/tables` 的 STC JSON 导出表；
- 新增 `targetforge/stc_json.py`、`targetforge/enemy_stats.py`；
- 运行时不再依赖 `unit_model`；
- 属性模型（类型锚点 + 标准等级曲线）预计算进 `catalog.json`；
- 成员详情无需重新读取原始 STC 文件；
- 发布仓库中的 `unit_model/` 已删除。

## 3. 敌人与怪组核查

- 全量实际敌人已纳入图鉴：
  - 全部敌人队伍约 **17,788**；
  - 关卡约 **3,908**；
  - 灰域节点约 **1,880**。
- 实际出场链路按 `spot.enemy_team_id ∪ mission.boss_team_id` 核对；
- 灰域节点与实际队伍的关联做过全量对照；
- `targettrain_cancollect` 明确为「靶机专训收藏池资格」，不是灰域战斗捕获资格；
- `7301601` 最终贮藏地实际 BOSS、`6630191` 靶机池队伍等边界案例已记录；
- 机场/后续刷新候选仍然属于**推断**数据：
  - 优先 `manual_spawns.json` 显式表；
  - 其次同 ID 族前缀推断；
  - 再退兄弟关继承 / 邻近窗口；
  - UI 标「可能刷怪（推断）」，不当作实际出场。

## 4. 本地靶机桥接（实验）

用于临时加入正常 `addCollect` 不允许的红框怪组。

- 只修改客户端 `Index/index` 响应中的 `targettrain_collect_user_info`；
- **只追加、不替换**服务器真实收藏；
- 不调用 `addCollect`，不写服务器；
- 桥接靶机只能直接进入战斗：
  - 不能删除、锁定、管理、同步或做任何服务器写入；
  - 游戏内删除会提示“非法操作”，这是预期现象；
- 停止桥接并重启游戏后，桥接靶机全部清空；
- 进入战斗闪退/卡死时，应立即停止桥接并恢复系统代理；
- 已验证 authcode + gzip 响应的解密、修改、重新加密流程；
- 12 个灰域目标（小怪 + BOSS）实测可进入战斗、可正常结算；
- 支持 PC 客户端与安卓模拟器模式：
  - PC：Windows 系统代理 + 重启游戏；
  - 模拟器：自动检测 ADB、`adb reverse`、模拟器全局 `http_proxy`；
  - 停止时恢复原代理、移除 reverse；
- 红框/蓝框允许混接；只要包含红框，整组按临时桥接处理；
- 蓝框也允许走桥接，属于向下兼容的「临时加入」。

## 5. UI 与主题

- 全新 Soft UI 亮色主题与深色模式（右上角太阳/月亮切换，`localStorage` 记忆）；
- 纯白底蓝色蝴蝶 Logo，已移除黄黑几何色块；
- 首页提示红框敌人不可正常加入，可考虑实验性桥接；
- 全怪组筛选改为淘宝式 tag 面板：
  - 怪种 tag 搜索加入；
  - 阵营 4 选 1；
  - BOSS / 非 BOSS；
  - 可作靶机 / 仅展示；
  - 总血量范围；
  - 单位数范围；
  - 队伍编号精确筛选；
  - 已选 tag 可逐个移除，支持一键清除；
  - 返回页面时保留筛选条件、分页和滚动位置；
- 灰域节点筛选（搜索、排序、点位类型、页码）在返回节点列表后保持；
- 关卡图鉴、关卡列表、怪组卡片、帮助页、抓包页均补齐浅色模式；
- 字号整体放大，怪组表格与图标进一步放大；
- 侧栏激活项默认深色底白字，悬浮变黄底黑字；
- 页面切换与侧栏高亮增加平滑过渡；
- 灰域/积分关卡的未证实推断候选统一归入「已屏蔽（过滤）」，附圆圈问号解释。

## 6. 安全与边界

- 桥接是本地客户端响应伪造，不会写入官方账号数据；
- 仅建议测试账号使用；
- 官方服务器端仍可能对靶机日志/记录做校验；
- 普通抓包与桥接不能同时占用系统代理；
- 所有代理/ADB 操作都应在停止时恢复，异常退出时应用会尝试恢复系统代理；
- 凭证只保存在本机应用数据目录，不应提交到 git 或外传。

## 补充：灰域「已屏蔽」的红蓝框口径

- 灰域节点内，**非红框（可收藏 / 可临时靶机）** 的实际队伍与推断候选统一归入「已屏蔽（过滤）」；
- 红框是实际战斗队伍，保留在正常场上列表；
- 屏蔽只是折叠到独立区块，展开后仍可查看详情或加入序列，不是删除数据；
- 积分关卡只折叠未证实的非红框机场/支援候选，实际场上队伍不动。

## 补充：关卡级屏蔽与分级

- 灰域区域节点列表新增「无收藏队伍的节点」折叠区，默认屏蔽；
- 该折叠区与正常节点共用搜索、排序、点位类型筛选条件；
- 关卡内部「已屏蔽（过滤）」拆为：
  - 一级屏蔽：原关卡实际非红框队伍 + 本关候选小怪；
  - 二级屏蔽：表外/其他无关怪组，单独折叠，避免想打特定怪组时被混在一起；
- 关卡列表如出现“整关没有可收藏队伍”，也会归入「已屏蔽的关卡」并遵守当前筛选条件。
